# Инструкции для ИИ-агента

## О проекте

Это веб-платформа для учеников и учителей. ИИ создаёт тесты с помощью локальной языковой модели. Ученики проходят тесты и отправляют ответы, а учителя получают доступ к ответам и результатам.

## Основной стек

- Backend: FastAPI в `backend/`
- Frontend: Next.js 16 в `web/`
- База данных: PostgreSQL, SQLAlchemy 2, Alembic
- Авторизация: Keycloak через OIDC
- Генерация тестов: Ollama, интеграция в `backend/app/llm/`
- Тесты backend: pytest
- Инфраструктура: Nginx и Docker Compose
- Дополнительно: Redis для кэша, RabbitMQ и worker для фоновых задач

## Роли и доступ

- `student` — проходит тесты и отправляет ответы.
- `teacher` — просматривает ответы и результаты учеников.
- `admin` — управляет пользователями, ролями и настройками платформы.

Проверяй права доступа на backend. Не полагайся только на скрытие элементов интерфейса.

## Работа с генерацией тестов

- Запрашивай генерацию тестов у Ollama только через backend.
- Проверяй и валидируй ответ модели перед сохранением.
- Храни тесты и связанные с ними ответы в PostgreSQL.
- Не добавляй секреты, пароли и токены в исходный код. Используй переменные окружения и обновляй `.env.example` без реальных значений.

## Правила работы

1. Перед изменениями изучи структуру проекта и существующий код.
2. Сохраняй текущие соглашения и не перезаписывай файлы без необходимости.
3. Делай изменения небольшими и связанными с задачей.
4. Для изменений backend добавляй или обновляй тесты pytest.
5. Для изменений схемы базы данных создавай миграцию Alembic.
6. Не утверждай, что тесты прошли, если ты их не запускал.
7. После работы сообщай, какие файлы изменены и как запустить приложение и тесты.
8. Если требование неоднозначно или важная часть не работает, сначала объясни проблему и предложи конкретный вариант.

## Қабат картасы және архитектуралық ережелер (4-сабақ)

Толық сипаттама мен қабат картасы: [docs/layers.md](docs/layers.md).
Проект строго следует 5-слойной чистой архитектуре (Clean Architecture):

| Қабат (Слой) | Жауапкершілігі (Ответственность) | Неге ТЫЙЫМ салынады (Запреты) |
|---|---|---|
| **Router** | Қабылдау, рөлдерді тексеру (`student`/`teacher`/`admin`), Service-ті шақыру, қателерді HTTP статусқа аудару (`Қате→HTTP`). | **Router-де SQL ЖОҚ!** Ешқандай тікелей сұраныс немесе ORM операторы болмауы керек. |
| **Schema** | Pydantic DTO: кіріс пен шығыс мәліметтер валидациясы (`<Кіріс> → <Шығыс>`). | Бизнес-логика немесе БД-мен байланыс жоқ. |
| **Service** | Таза бизнес-логика мен бизнес-ережелер. Тек жеке Domain Exception лақтырады. | **Service-те HTTPException ЖОҚ!** Сервис HTTP/FastAPI туралы білмейді. |
| **Repository** | Дерекқормен жұмыс (SQLAlchemy 2 `select`, `insert`, `update`). Жалғыз DB нүктесі. | HTTP, Pydantic немесе роутерге тәуелділік жоқ. |
| **Model** | SQLAlchemy Declarative кестелері (`quiz_tests`, `quiz_questions`, `submissions`, т.б.). | Бизнес-логика жоқ. |
| **Қате→HTTP** | Domain Exceptions → HTTP Codes (`TestNotFoundError` → 404, `QuizValidationError` → 422). | Қателерді өңдеусіз қалдыруға болмайды. |

### Біздің мызғымас ережелер:
1. **Router-де SQL жоқ, service-те HTTPException жоқ.**
2. **Құпиялар тек `.env`-те.**

## Обязательные ограничения и безопасность (AI Guardrails)

Полный регламент зафиксирован в [RESTRICTIONS.md](RESTRICTIONS.md). ИИ обязан строго соблюдать следующие принципы:

1. **Режим обязательного подтверждения (Human-in-the-Loop):**
   - Все потенциально опасные и модифицирующие операции требуют **предварительного явного согласия пользователя**.
   - Запрещено выполнять без разрешения: удаление файлов, установку/удаление зависимостей, накат миграций Alembic, запуск/остановку контейнеров Docker, операции Git (`commit`, `push`, сброс веток, слияние).
   - Сначала объясни планируемое действие, покажи команду или diff и дождись подтверждения пользователя.

2. **Защита паролей и конфиденциальности (Zero-Knowledge):**
   - **Строгий запрет на чтение секретов:** никогда не читай и не открывай файлы `.env`, `.env.*`, приватные ключи (`*.pem`, `*.key`), сертификаты, файлы авторизации Keycloak и дампы БД.
   - Работай только с шаблонными файлами (`.env.example`) с фиктивными плейсхолдерами.
   - Никогда не запрашивай реальные пароли или токены у пользователя.
   - Никогда не выводи пароли, токены или учетные данные в чат, логи или код.
   - Никакого хардкода учетных данных в коде: все параметры передаются через переменные окружения.

3. **Технические ограничения безопасности:**
   - **Keycloak / OIDC:** проверка ролей (`student`, `teacher`, `admin`) строго на Backend в FastAPI. Запрещено обходить или упрощать авторизацию.
   - **PostgreSQL:** защита от SQL-инъекций (только ORM и параметризованные запросы). Запрещены `DROP TABLE`, `TRUNCATE`. Изменения схемы — только через миграции Alembic.
   - **Ollama:** запросы к модели только через Backend. Ответы модели валидируются схемами Pydantic; запрещено использовать `eval`/`exec`. Санитизация промптов от Prompt Injection.
   - **Next.js:** никаких приватных секретов в клиентском бандле (переменные без `NEXT_PUBLIC_`). Защита от XSS.
   - **Docker & Сеть:** внутренняя изоляция БД, брокеров сообщений и Ollama без лишних открытых портов наружу. Запрещено удалять тома данных.
